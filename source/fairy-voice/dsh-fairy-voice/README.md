# dsh-fairy-voice

给 DSH 加一套 Fairy 语音：每个回合结束自动用本机 **Fairy 音色**播报最终结果，
同时保留 [pi-fairy](https://github.com/ymd-physics/pi-fairy) 的 44 段事件音效。

语音合成只连接本机 `127.0.0.1:9880` 的 GPT-SoVITS，不把对话内容发往第三方。

---

## 这是什么 / 不是什么

| | |
|---|---|
| ✅ 是 | 回合结束语音汇报 + Fairy 固定事件音效，两套开关相互独立 |
| ✅ 是 | 本机 GPT-SoVITS 代理：自动选择 Fairy / 艾莲音色、语速可调、支持试听 |
| ❌ 不是 | 云端朗读。只有当前回合已经显示在页面里的最终回复会送往本机 TTS |
| ❌ 不是 | 上游官方作品。上游是 [橙汁本色](https://github.com/Chengzhibense/Fairy-DSH) 的 Fairy-DSH |

自动汇报会移除代码块、表格、链接和 Markdown 标记，只朗读约 220 字以内的结论。
TTS 失败时不会静默丢失反馈，会回落到对应的 `success` / `aborted` / `error` 音效。

素材来自 `ymd-physics/pi-fairy` 的 `modules/voice/sounds/`：44 个 WAV，1 声道 / 32 kHz / 16 bit PCM，共 9.28 MB。

## 装

### 让 Agent 装

把这段丢给 DSH Agent：

> 从 `<仓库目录>` 安装 `dsh-fairy-voice` 到我的 `web-desktop` profile。
> 装完执行 `dsh --profile web-desktop --dump-config` 确认已挂载，然后让我重启 DSH。

### 自己装

```powershell
dsh plugin --profile web-desktop add <包路径>\dsh-fairy-voice.tgz
```

> **profile 名要换成你自己的。** 本插件是在 DSH Desktop（EAC）上做的，那个客户端用的是
> `web-desktop`；官方 web 版通常是 `web`。装错 profile 的表现是「装成功了但界面上什么都没有」。

装完**重启 DSH**。回合结束自动汇报默认开启；事件音效默认关闭，可在
设置 → **Fairy 语音** 中分别控制。GPT-SoVITS 未运行时，首次播报会尝试执行
`D:/GPT-SoVITS/start-api.bat` 并等待服务就绪。

### 卸载

```powershell
dsh plugin --profile web-desktop remove dsh-fairy-voice
```

插件在 `~/.dsh/fairy-voice/` 下留了一个目录（配置 + 音效副本）。想彻底清干净就删掉它：

```powershell
Remove-Item "$env:USERPROFILE\.dsh\fairy-voice" -Recurse -Force
```

## 用

### 输入框左边的控件

- **圆点按钮**：总开关。开启时会先解锁浏览器音频（浏览器要求先有用户手势才允许出声），
  然后预解码最常用的几条，所以第一次触发不会有延迟。
- **音量滑块**：0–100%，同时控制 Fairy 播报和事件音效。

### 设置 → Fairy 语音

分组的逐条开关，每条都能**单独试听**（▶ 按钮，不受总开关限制）。另外还有：

| 项 | 说明 |
|---|---|
| 多段语音选择 | 带多段素材的事件可展开逐段勾选，只有选中的素材会参与随机播放；每段都能单独试听 |
| 回合结束语音汇报 | 默认开启。按终局状态播报完成、停止、错误或长度上限 |
| 音色 / 语速 | 从本机 `D:/GPT-SoVITS/voices` 自动发现；可直接试听 |
| 统一语气 | 对话语音汇报与启动页统一使用 `intro` 参考声线，不再按结果切换情绪 |
| 久坐提醒间隔 | 分钟。**该触发器默认关闭** —— 每小时响一声是打扰，想要自己开 |
| 上下文告警阈值 | 默认 80%。回落到阈值下 5 个百分点才重新武装 |
| 余额告警阈值 | 与余额同币种，默认 10 |
| 诊断信息 | 各信号源的订阅状态 + 最近 14 次触发记录。**不含任何对话内容**，可以直接贴出来 |

### 配置文件

`~/.dsh/fairy-voice/config.json`。界面上能改的这里都能改，改完重启即可生效。

自动汇报相关字段：

```json
{
  "autoReport": true,
  "tts": {
    "endpoint": "http://127.0.0.1:9880",
    "voice": "Fairy",
    "speed": 1
  }
}
```

对话汇报和启动语音都读取 `D:/GPT-SoVITS/voices/<音色>/ref-intro.wav` 与同名 `.txt`。
缺少该参考时会回落到音色的 `ref.wav` / `ref.txt`。
参考节奏核对自《绝区零》3.3 剧情实机片段、Fairy 待机语音和 HDD 彩蛋；
这些素材仅用于本机个人语音配置，不代表米哈游官方发布。

> 如果你是从旧包名 `dsh-pi-voice` 升上来的：`~/.dsh/pi-voice/` 会被**自动沿用**，
> 配置与你自换的音效原地生效，不用手动搬。想迁到 `~/.dsh/fairy-voice/` 就把旧目录改名后重启 DSH；
> 两个目录同时存在时**一律以 `~/.dsh/fairy-voice/` 为准**。

### 音效目录

首次启动会把包内素材**播种**到 `~/.dsh/fairy-voice/sounds/`。

- 只补缺失文件，**绝不覆盖同名文件** —— 你自己换掉的音效不会被下次启动冲掉。
- 想换成自己的素材：把同名 WAV 放进去即可（保持 `welcome-1.wav` 这样的文件名）。
- 想整个换目录：在 `config.json` 里设 `soundsDir`。

> 为什么不在 `node_modules` 里放音效：那是 pnpm 随时会重建的目录。你的东西一律留在 `~/.dsh/fairy-voice/`。

## 事件映射

见 **[`docs/事件映射.md`](docs/事件映射.md)** —— 逐条列了每个触发器用的确切信号、置信度、
以及哪些**没接线**和为什么。

一句话版本：**23 条接了可靠信号，1 条（输入提示音）上游没说明用途。**
权限的请求、批准、拒绝三条全部接线 —— 早期版本曾把「请求」接在授权瀑布流上，
那是错的（官方授权插件先注册且不交出 `next()`，根本轮不到我），已改走会话层的待处理交互表。

## 语音链路

| 环节 | 行为 |
|---|---|
| 触发 | DSH 发出 `turn/end` 终局事件 |
| 取文 | 只读取当前会话已经渲染出的最终回复，不读取思考过程 |
| 清理 | 移除代码、表格、链接和 Markdown，最多约 220 字 |
| 合成 | 宿主代理到本机 GPT-SoVITS，自动切换 Fairy / 艾莲权重 |
| 播放 | 使用浏览器已解锁的音频上下文；播报优先级高于普通事件音效 |
| 失败 | UI 状态区显示原因，并回落到对应的固定音效 |

## 故障排查

| 症状 | 原因 / 怎么办 |
|---|---|
| 设置里根本没有「Fairy 语音」 | 装错 profile 了。确认装的是你正在跑的那个 profile |
| 回合结束不播报 | 检查「回合结束语音汇报」是否开启、是否静音，以及状态区的 TTS 错误 |
| TTS 服务没起来 | 确认 `D:/GPT-SoVITS/start-api.bat` 存在，或手动启动 GPT-SoVITS API |
| 某个音色不可选 | 音色目录必须同时包含 `gpt.ckpt`、`sovits.pth`、`ref.wav` |
| 只有部分事件响 | 看 设置 → Fairy 语音 → 状态区。哪一行写着「失败」或「没有」，就是那一路信号在这个宿主上不可用 |
| 全都不响，状态区一片红 | 宿主没起 `webServer` 或路由被占。重启 DSH 再看 |
| 声音听着比别的提示音小 | 素材是 32 kHz 单声道、原始电平不一。调 `config.json` 的 `packGain`（>1 放大），或就地替换 WAV |
| 和别的 UI 插件打架 | **不会**。本插件不读也不改任何 DOM 选择器，只往两个插槽里塞自己的节点 |
| 换了音效但没生效 | 播种**只补缺失文件**。同名文件已存在时不会被覆盖 —— 确认你放的是 `~/.dsh/fairy-voice/sounds/` 下那个 |

## 自检

```powershell
npm test
```

三套，都不启动 DSH、都在**临时目录**里跑、跑完自动清理，不碰你真实的 `~/.dsh`：

| 套件 | 覆盖 |
|---|---|
| `test/selftest.mjs`（15 项） | 宿主侧：素材与清单一对一、5 条路由注册、音效静态服务、**目录穿越防护**、配置读写与非法值收敛、首次播种 |
| `test/client-detectors.mjs`（41 项） | 客户端：真实事件形状、`turn/end` 终局、自动汇报、TTS 失败回落、历史加载不出声、权限请求与批准/拒绝、冷却、优先级抢占 |
| `test/data-dir.mjs`（3 项） | 数据目录解析：新目录优先、旧包名目录回落、两者并存时以新目录为准 |

客户端那套是重点：它能在**不安装、不重启**的前提下验证检测逻辑。

### 已经实测过的部分

另外用**另一个端口**把这套 profile 真启动了一次（验证完即关闭，不影响你正在用的实例）：

- 插件装载无报错 —— 排除了 `plugin tree failed to load` 这个最致命的风险
- `/fairy-voice/status` → 200，素材 44/44 就绪，24 个触发器
- `/fairy-voice/sounds/welcome-1.wav` → 200 `audio/wav`，RIFF 头正确
- 目录穿越与清单外文件名 → 均 404
- 首页 `__DSH_BOOT__` 启动图里出现 `dsh-fairy-voice` 条目，4 个 `inject` 依赖全被接受
- `/plugins/??dsh-fairy-voice/client.js` → 200，内容含 `__ModuleLoader__.load`

**唯一没验的是真实浏览器里的音画效果** —— 那需要你的会话和一次用户手势来解锁音频。

## 已知限制

1. **后台会话没有回合事件**。宿主的事件窗口只对**在台上**（当前选中）的会话开放，
   后台会话只暴露粗粒度的 `running` 布尔。所以切到别的会话时，原会话的回合不会响。
2. **DSH 关闭时可能听不到告别音**。没有关闭 API，只能用 `pagehide`；浏览器卸载期间启动的音频常被丢弃。
3. **同会话并存多个阻塞弹窗时只响一个**。待处理交互表按会话只保留优先级最高的那一个，
   所以两个弹窗叠在一起时只会看到最上面的。实际使用里很少遇到。
4. **权限音覆盖偏宽**。走的是「任何待处理交互」，所以提问、计划确认这类阻塞弹窗也会响 ——
   这是照 pi-fairy「Permission phase and other blocking UI prompts」的原意做的。不想要就关掉这一条。
5. **模型切换有首帧延迟**。信号来自 `model/selection` 事件，打开会话的第一帧只用来建立基线。
6. **依赖宿主内部契约**。`turn/end` 的 `reason.kind`、事件窗口的 `change.kind`、`contextPressure`
   投影、`PendingApproval.result` 等都是 DSH 的客户端契约。DSH 大版本升级后可能位移 ——
   但失效的表现是**某个触发器不响**，插件本身不会崩：每个信号源各自独立订阅、各自捕获异常，
   状态区会直接告诉你哪一路掉了。
7. **播报内容取决于最终回复能否从 DOM 投影中读出**。DSH 大版本调整聊天节点属性时，
   自动汇报可能只读出最近一次最终回复；状态区会显示读取与合成阶段。
